# Course Teaching Archive（课程教学成果归档）

Teaching-Works-Lab 下**课程大纲 + 教案**的生成结果归档仓库。只放已生成（或明确处于草稿状态）的大纲与教案；生成它们的 Skill 分别在 `course-teaching-workflows`（大纲）与 `lesson-plan-compiler`（教案），不在此仓库。

## 目录约定

```text
course-teaching-archive/
├── version/                 # 全局版本场景，只定义一次，所有课程共用
│   ├── 2025.md              # 保守基线
│   └── 2027.md              # 未来场景
├── course/
│   └── <课程名>/
│       ├── README.md        # 课程清单：本课程有哪些版本
│       ├── 2025/            # 每个版本 = 一个自包含原子
│       │   ├── README.md    # 本版本自查清单
│       │   ├── 大纲/
│       │   │   ├── 2025-<课程名>-课程大纲.md     # 事实源，可 diff
│       │   │   └── 2025-<课程名>-课程大纲.docx   # 学校定稿，编译产物
│       │   └── 教案/
│       │       ├── 2025-<课程名>-教案.md          # 一份，内含 lesson-01…lesson-N
│       │       └── 2025-<课程名>-教案.docx
│       └── 2027/
│           ├── README.md
│           ├── 大纲/
│           └── 教案/
├── scripts/
│   └── check_structure.py   # 结构自检：原子完整 / md-docx 成对 / 版本前缀一致
└── .gitattributes
```

## 三条硬规则

1. **版本目录是原子**：`<课程名>/<版本>/` 内必须自包含「大纲 + 教案」各一份，缺一件就是破损。2025 与 2027 各自独立、可并行生成/审查。
2. **md 是事实源，docx 是编译产物**：每个 `.docx` 必须有同名前缀的 `.md`。改内容改 `.md`，再重新编译 `.docx`。
3. **文件名自带版本前缀**：`2025-` / `2027-` 必须与其所在版本目录一致；文件被拖错目录也能一眼看出。

## 校验

```powershell
py -3.12 scripts/check_structure.py
```

## 新增一门课

1. 在 `course/` 下建 `<课程名>/`，复制一份课程 `README.md`；
2. 建 `2025/`、`2027/`（按需），各含 `README.md`、`大纲/`、`教案/`；
3. 把生成结果放进对应目录，文件名按 `2025-<课程名>-课程大纲.md/.docx` 命名；
4. 跑 `check_structure.py` 确认原子完整。
