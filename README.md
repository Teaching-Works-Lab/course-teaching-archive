# Course Teaching Archive（课程教学成果归档）

Teaching-Works-Lab 下**课程大纲 + 教案**的生成结果归档仓库。只放已生成（或明确处于草稿状态）的大纲与教案；生成它们的 Skill 分别在 `course-teaching-workflows`（大纲）与 `lesson-plan-compiler`（教案），不在此仓库。

## 目录约定

```text
course-teaching-archive/
├── version/                 # 全局版本场景，只定义一次，所有课程共用
│   ├── 2025.md              # 保守基线
│   └── 2027.md              # 未来场景
├── course/
│   └── <课程名>/            # 课程全名，如 程序设计基础（C&C++）Ⅰ
│       ├── README.md        # 课程清单：本课程有哪些版本
│       ├── 2025/            # 每个版本 = 一个自包含原子
│       │   ├── README.md    # 本版本自查清单
│       │   ├── 大纲/        # 文件名保留课程代码原名，如 25JX31802-…
│       │   └── 教案/        # 尚未生成时为空（仅 .gitkeep）
│       └── 2027/
│           ├── README.md
│           ├── 大纲/
│           └── 教案/
├── scripts/
│   └── check_structure.py   # 结构自检：原子 / 目录齐全 / md-docx 配对提醒
└── .gitattributes
```

## 硬规则

1. **版本目录是原子**：`<课程名>/<版本>/` 内自包含「大纲 + 教案」目录；2025 与 2027 各自独立、可并行生成/审查，互不依赖。
2. **文件名保留课程代码原名**（如 `25JX31802-程序设计基础（C&C++）Ⅱ-WPS兼容版.docx` / `25JD31401-…`），不用版本年作前缀——版本归属由所在目录（`2025/`、`2027/`）体现。
3. **md 是理想事实源**：大纲若只有 `.docx`（缺同名 `.md`）会由自检**告警提示待补**，不阻断归档；补 `.md` 后应与 `.docx` 同名成对。
4. **每个版本目录有 `README.md` 自查清单**；覆盖其文件、缺件、脱敏状态。

## 校验

```powershell
py -3.12 scripts/check_structure.py
# 结构完整退出 0；docx 缺同名 md 等以 [警告] 提示，不失败
```

## 新增一门课

1. 在 `course/` 下建 `<课程名>/`，写课程 `README.md`（课程代码 + 版本清单）；
2. 建 `2025/`、`2027/`（按需），各含 `README.md`、`大纲/`、`教案/`；
3. 把定稿大纲放进对应版本 `大纲/`，**保留课程代码原名**；
4. 教案未生成时 `教案/` 只留 `.gitkeep`；
5. 跑 `check_structure.py` 确认原子完整、检查配对告警。

## 隐私（公开仓库）

发布前先脱敏：去掉主讲教师姓名/工号、学生信息、内部考核比例细节与本地路径。示例内容保持虚构、去身份化。
